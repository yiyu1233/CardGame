# 卡牌对战游戏（Godot 4.7）

炉石传说 / 影之诗风格的 **双方随从对战** 框架：双方英雄各 30 点生命、随从上场与攻击、
嘲讽 / 圣盾 / 冲锋 / 突袭 / 风怒、战吼与亡语、法术指定目标、法力水晶递增、疲劳伤害，
内置一个会自动出牌与攻击的 **敌方 AI**，并保留 **管理员登录后可增删卡牌** 的功能。

## 一、如何运行

方式 A（**双击即玩**，推荐）：

| 文件 | 用途 |
| --- | --- |
| `启动游戏.bat` | 以图形窗口启动游戏。启动失败时会保留窗口并给出排查提示 |
| `启动游戏(带控制台).bat` | 同上，但优先使用带控制台的引擎，退出后保留窗口，方便看引擎日志 |

两个文件都会自动查找 Godot 4 可执行文件，顺序为：

1. 环境变量 `GODOT` 指向的 exe
2. 本目录下的 `godot\` 子目录（把绿色版 Godot 解压到这里最省事，换版本也不用改脚本）
3. 本机常见安装位置（含本机的 `D:\Godot_v4.7.1-stable_win64.exe\` 那个目录）
4. `PATH` 里的 `godot`

都找不到时会打印中文之外的英文提示，并告诉你三种补救方式。

额外参数会原样转给 Godot，例如跑 60 帧后自动退出：

```powershell
.\启动游戏.bat --headless --quit-after 60
```

方式 B（IDE / 编辑器任务）：`.vscode/tasks.json` 里已经注册好「启动游戏」「启动游戏（带控制台）」两个任务，
在编辑器里运行任务（VS Code 系为 `Ctrl+Shift+B` 或「终端 → 运行任务」）即可，无需敲命令。

方式 C（Godot 编辑器）：启动 Godot → 「导入 / Import」 → 选择本目录的 `project.godot` → F5 运行。

方式 E（**发布包**：单独的游戏 + 启动器，给别人电脑用）：见文末「打包发布：单独游戏与启动器」一节，
一条命令产出一个自包含的文件夹（双击里面的 `Launcher.exe` 即玩）与同名 zip；
加 `-OutDir "D:\某个文件夹"` 可以让成品直接落到项目之外的独立文件夹里，项目目录只留源码。

> 注意：发布包默认落在 `release\`，`-OutDir` 可以改到任何地方；它跟上面方式 A 的开发启动脚本互不冲突。

方式 D（命令行，手动指定引擎）：

```powershell
& 'D:\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64.exe' --path 'c:\Users\DAYBR\CodeBuddy\codes\CardGame'
```

> 注意：你机器上的 `D:\Godot_v4.7.1-stable_win64.exe` 实际是一个**文件夹**，真正的 exe 在它内部。
>
> 维护提示：所有 `.bat` 的**内容**都刻意保持纯 ASCII（中文只出现在文件名与本文档里）。
> 原因是 cmd.exe 按控制台代码页逐行解析批处理文件，UTF-8 的中文内容会破坏行的切分，
> 进而把命令拆错（实测过：`if defined` 会被截成 `defined` 并报“不是内部或外部命令”）。
> 所以请不要往 `.bat` 里加中文，需要中文说明就写在这里。

## 二、操作方式

| 操作 | 说明 |
| --- | --- |
| **开局起手换牌** | 新对局开局抽 **4 张** 后会弹出「起手换牌」面板：**点击想换掉的牌**（可多选，选中的卡面会亮起）→ 点「确认换掉这 N 张」，这些牌洗回牌库后重抽同样张数；不想换就点「全部保留」。**确认之前面板会挡住底下的手牌与战场**，所以不会误操作 |
| **悬停手牌 / 随从** | 在卡牌右侧弹出完整效果说明（费用 / 类型 / 攻血 / 关键字 / 战吼 / 亡语 / 衍生物 / 描述），右侧空间不足自动翻到左侧 |
| **点击手牌 / 随从** | 详情面板固定显示，直到出牌、右键或取消选择 |
| **拖拽手牌到战场** | 出牌：随从 / 护符拖到**我方战场的某一格**（**拖到哪个格子就放进哪个格子**，指向的格子会描一圈：**绿=可放 / 红=被占用或不是这一侧**），法术拖到高亮的目标（敌方英雄 / 随从）上松手；拖到无效区域则取消。**法力不足 / 战场已满的牌照样能拿起来比划**：幽灵卡显示成红色禁止样式、落点不点亮，操作栏与松手后的日志都会说明具体原因（需要几点 / 当前几点） |
| **拖拽我方随从到敌方目标** | 发起攻击（有嘲讽时必须先打嘲讽随从） |
| **打出城邦** | 城邦卡只有**一个落点**：主战者左侧的**城邦格**（不占 7 格战场），所以拖到我方战场任意位置都会进那一格；城邦格已被占用时打不出，操作栏会说明原因 |
| **把随从移入 / 移出防御格** | **移入**：出牌时把随从拖到**战场行正中那一格（画着「横置 / 防御」）**，或把场上已有的随从拖到那一格；**移出**：把防御格里的随从**拖回我方后排**。两个动作**共用一个名额，一回合只能用一次**，且只能在自己的回合做；被拒绝时操作栏给出原因。同一侧同时只有一个，后进的会把先前的挤回后排 |
| 点击手牌 | 与拖拽等效：无需目标的牌直接打出（**自动放进最早的空位**）；需要目标的牌进入“选择目标”状态（此时**整条手牌抬起、张开并移到中央偏右**，原版《影之诗》的放大态），再点目标打出；打不出时给出具体原因（如「法力不足：「雷电骑士」需要 4 点，当前只有 2 点」） |
| 点击「主战者框」 | 选目标状态下点上下正中的头像框＝指定该英雄为目标；点击判定是**圆形**的，框四角的点击会落到它后面的卡牌上 |
| **点击我方带技能的单位** | 发动**主动技能**（消耗 PP = 法力）：不需要目标 → 立刻发动；需要目标 → 进入「选择技能目标」，再点高亮目标发动。若**本回合已用过 / PP 不足 / 被横置或冻结**，点它会**回落到「选择攻击目标」**，操作栏给出不能发动的原因（如「PP 不足：需要 2 PP，你现在只有 1」） |
| 点击我方已准备好的随从 | 进入“选择攻击目标”状态（绿色边框表示可攻击） |
| 再点击敌方随从 / 敌方英雄 | 发起攻击 |
| 右键点击任意位置 / 手牌 | 取消当前选择或取消拖拽 |
| **结束回合**（中线右端的圆形按钮） | 交给敌方 AI，AI 出牌 → 攻击 → 结束，然后回到我方；开启“二次确认”时若还有法力 / 可攻击随从会先询问。按钮里显示当前回合数，周围一圈是我方能量点 |
| **记牌器**（中线左端的圆形按钮） | 从**右侧滑出**的抽屉（只盖住右侧日志栏、**不占中间场地**），查看本局双方各自**已使用的卡牌**：费用、名称、类型与张数，以及牌库 / 手牌 / 墓地 / 疲劳；再点一次该按钮或按 `Esc` 收起 |
| **设置**（顶栏） | 悬停详情开关、敌方手牌显示、结束回合二次确认、手牌扇形角度；拖动滑块实时预览，松手或关闭窗口时写入 `user://settings.cfg` |
| **认输**（顶栏） | 二次确认后直接判负结束本局 |
| 重开一局 | 用最新卡表重新开局 |

拖拽交互细节：拖动超过 8px 后原卡半透明、由顶层 `DragLayer` 上的“幽灵卡”跟随鼠标；
合法放置区（战场行 / 可攻击目标）以黄色边框高亮，操作栏实时显示当前拖拽的卡牌与放置提示。
**卡牌的整个卡面都能按下拖动**（包括中间的大段描述文字区域），随从的整个卡面同理——
这靠 `UiUtil.make_decorative()` 把卡面里的装饰性子控件全部设为不接收鼠标事件实现，
否则 `RichTextLabel` / `HSeparator` / 占位 `Control` 会把按下与拖动事件就地吃掉（详见「扩展指引」）。

界面采用主流卡牌游戏的**居中对称布局**，上下两个半场关于**中线**严格互为镜像：
敌方半场（手牌背 → 敌方英雄 → 敌方战场，战场紧贴中线）⇄ 中线 ⇄ 我方半场（我方战场 → 我方英雄 → 手牌，战场紧贴中线）。
- 双方**战场行到中线距离完全相等**，两侧随从都紧贴中线"面对面"排布
- **敌方手牌卡背与底部我方手牌扇形互为镜像**：我方向上凸的扇形弧线，敌方向下凸（旋转方向相反）
- 我方手牌为**居中扇形排布**，战斗日志固定在右侧边栏。
- 中线是一条亮色**接缝**（上下半场的分界），两侧战场行各画出**7 个随从槽位**，随从正好落在槽位里；
  槽位右上角显示「我方战场 3 / 7」这类计数（原来是一行独立的标题文字，已省掉以腾出高度）。
  对齐靠「两侧补等宽空槽占位」实现：整行子节点总宽恒等于 7 个槽位宽，所以随从数是奇数或偶数都不会错开半格。
- **中线两端各一个圆形按钮**：左端「记牌器」、右端「结束回合」（见下一条），都垂直居中于中线、贴在中线两端，
  正好落在 7 个战场槽位之外的空白条里，不压随从也不挡落点。
- **中线右端是圆形「结束回合」按钮（影之诗风格）**：按钮里直接显示**当前回合数**，
  我方的 **10 颗能量点环绕按钮一圈**（与别处同一套「可用 / 已花费 / 未解锁」配色），
  圆环下方标注按钮功能（我方回合＝「结束回合」/ 对手回合＝「对手回合」/ 结束＝「对局结束」）。
  它叠在两块战场之间的空档里，正好在中线上、又不压住任何随从槽位。
- **上下两侧正中是「主战者框」**（影之诗式领袖头像框）：双环圆盘 + 盘内的名字与占位徽记，
  盘右侧压着**红色血量徽章**，下方是**黄色护甲徽章**（有护甲才显示）；
  敌方的 **10 颗 PP 珠**摆在圆盘左侧（跟「3/6」数字，复用与回合按钮同一套三态判定与配色）。
  圆盘按战场行的实际位置**自动让开**（敌方往上、我方往下），既不遮住随从也不会抢走随从的点击；
  点击圆盘＝指定该英雄为目标，可被指定时圆盘亮起黄圈。
  （没有立绘素材时盘内是绘制的盾形徽记占位，有素材后在这里贴 `TextureRect` 即可。）
- **计数搬到了竞技区角上的独立信息框**：敌方在**右上**、我方在**左下**，2×2 显示
  **牌库 / 手牌 / 墓地 / 疲劳**，关键状态同样变色（牌库见底、手牌已满、已有疲劳）；信息框不吃鼠标事件，底下的卡牌照常拖拽。
- **我方手牌默认停靠右侧**，把下方正中让给主战者框（牌多时自动互相叠一点，整条压进右半边）；
  **点牌进入选目标状态时整条手牌平滑滑到下方正中**并展开扇形，选完 / 右键 / 出牌后滑回右侧。
- **敌方手牌在上半场左上角**（与主战者框分开、只占左半边），仍是卡背 + 镜像扇形，和停靠右侧的我方手牌一左一右。
- 轮到我方时圆形按钮轻微呼吸，对手回合时按钮变暗并禁用；回合切换时场地中央闪一条「我方回合 / 敌方回合」横幅。
双方信息栏显示：剩余牌库、手牌数、墓地数、疲劳层数与护甲（护甲见主战者框徽章，法力见回合按钮周围的能量点与敌方框的 PP 珠）。

### 如何新增一个机制（3 步）

机制代码**只有一个区块**：[`scripts/Mechanics.gd`](scripts/Mechanics.gd) 里 `_register()` 的「新增机制就在这里加」，
以及文件末尾的「钩子实现」。加机制按这个顺序做：

1. `scripts/CardData.gd` 的 `Keyword` 枚举加一个 ID（并在 `KEYWORD_NAMES` / `KEYWORD_KEYS` 各补一行）；
2. 在 `Mechanics.gd` 的「新增机制就在这里加」区块里加**一行** `_reg(...)`；
3. 卡表 JSON 的 `keywords` 写上对应 key（如 `"stalwart"`）——管理员面板会自动多出一个复选框。

如果机制只是**布尔规则**，第 2 步就够了：在 `_reg(..., [标志名])` 里声明标志位，引擎会在判定点自动生效（不用改引擎）：

| 标志位 | 效果 | 引擎读取位置 |
| --- | --- | --- |
| `cannot_attack` | 无法攻击 | `BoardUnit.can_attack()` |
| `no_attack_cost` | 攻击不消耗本回合次数 | `GameManager.attack()` |
| `untargetable_by_foe` | 不能被敌方指定为目标 | `Mechanics.can_be_targeted()` |
| `immune_damage` | 免疫所有伤害 | `GameManager.deal_damage_to_unit()` |
| `only_one_damage` | 受到的任何伤害减为 1 | `GameManager.deal_damage_to_unit()` |

例：`_reg(CardData.Keyword.STALWART, "坚壁", "受到的任何伤害减为 1。", {}, [FLAG_ONLY_ONE_DAMAGE])` —— 就这一行，
石壁巨像（f010）就真的只受 1 点伤害了。要**主动做事**（吸血 / 剧毒 / 复生这类）再写个钩子函数挂上去。

**安全网**：`Mechanics.audit()` 会比对「枚举 / 注册表 / 名称表 / key 表 / 标志位名」是否一致，
`tools/mechanics_api_test.gd` 断言它是干净的——漏注册、标志位名字写错都会被当场抓住（不会静默失效）。

**词条自检**：`tools/keyword_matrix_test.gd` 把 12 个词条逐个跑一遍「满足条件就该触发 + 条件不满足时不触发」，
并给出词条两两组合的清单（结尾打印成表）。当前结论：

| 组合 | 类别 | 结论 |
| --- | --- | --- |
| 潜行 + 嘲讽 | 冲突 | 嘲讽靠「敌方必须先打它」生效，潜行让它不能被指定 → 潜行期间嘲讽形同虚设 |
| 冲锋 + 迟钝 | 冲突 | `cannot_attack` 标志位优先，有冲锋也只能站着 |
| 突袭 + 迟钝 | 冲突 | 同上，当回合连随从都打不了 |
| 风怒 + 迟钝 | 冲突 | 攻击次数上限照算，但攻击本身被禁用 |
| 剧毒 + 坚壁 | 冲突 | 坚壁只压伤害，剧毒是直接把生命置 0 —— 「任何伤害减为 1」挡不住它 |
| 复生 + 潜行 | 冲突 | 复生按卡数据重建单位 → 运行时已经解除的潜行会被还原 |
| 冲锋 + 突袭 | 压制 | 冲锋盖过突袭（能打英雄），突袭没有额外贡献 |
| 圣盾 + 坚壁 | 压制 | 顺序固定：先走圣盾（该次伤害为 0），破盾后才轮到坚壁减伤 |
| 剧毒 + 圣盾 | 压制 | 被盾挡下算「没造成伤害」→ 剧毒不结算 |
| 风怒 + 冲锋 | 叠加 | 当回合两次攻击都能打英雄 |
| 吸血 + 剧毒 | 叠加 | 同一份伤害事件上两个钩子都跑 |
| 潜行 + 法术伤害 | 叠加 | 潜行不影响它对全队法术的加成 |
| 迟钝 + 法术伤害 | 叠加 | 迟钝只禁攻击，法伤照给 |
| 复生 + 迟钝 | 叠加 | 复生只改生命值，词条照旧保留 |
| 嘲讽 + 圣盾 | 叠加 | 一个管选目标、一个管减伤 |

**冲突时谁说话：后到者覆盖。** 上面标成「冲突 / 压制」的组合说的是「这两个同时挂在一个单位身上
会互相拆台」；引擎对**运行时被赋予**的那一条另有规矩 —— **后给予的效果覆盖掉与之冲突的旧效果**：
给一个潜行单位赋予嘲讽，潜行立刻消失、嘲讽真的成立；反过来也一样（嘲讽在前的，被后到的潜行顶掉）。
在这张互斥表里登记的（见 `Mechanics._register()` 末尾的 `_reg_conflict`）目前是：

| 互斥的一对 | 为什么扯在一起 | 后到者覆盖的样子 |
| --- | --- | --- |
| 潜行 ↔ 嘲讽 | 一个「不能被指定」，一个「必须被打它」 | 后赋予嘲讽 → 潜行消失；后赋予潜行 → 嘲讽消失 |
| 迟钝 ↔ 冲锋 | 一个不能攻击，一个当回合就能攻击 | 后赋予冲锋 → 迟钝消失（当回合就能打） |
| 迟钝 ↔ 突袭 | 同上 | 后赋予突袭 → 迟钝消失 |
| 冻结 ↔ 冲锋 / 突袭 | 冻结 = 到某回合为止不能攻击；后者 = 当回合就能攻击 | 后赋予冲锋 → 解冻；先有冲锋再被冻结 → 冲锋消失 |

冻结不是词条，所以在 `Mechanics.status_conflicts()` 里单列。
这条规则同样进了 `Mechanics.audit()` 的自检：表里的项若指向未注册机制、或者只登记了单向，都会被断言抓住。
这条规则只管**运行时被赋予**的效果：卡数据里本来就印着两个互斥词条时（比如一张卡自带
潜行 + 嘲讽）没有先后之分，两个都留着 —— 那是配卡层面的取舍，不是这条规则的事。

## 卡牌制作升级：效果链（战吼 / 亡语多段）与主动技能

管理员在「卡牌管理」里可以做出更复杂的卡。

### 1. 效果链：战吼 / 亡语按顺序整合多条效果

- 战吼 / 法术 / 安放（护符 · 城邦）的效果，以及**亡语**，都从「一条效果」升级成**一条效果链**：
  面板里「＋ 添加效果」可加多条，用 **↑ / ↓ / 删除** 调整顺序与增删，结算时**严格按面板里的顺序**逐条执行。
- 每条效果 = **效果 ID + 数值 + 目标类型 + 衍生物 ID**（只有召唤类需要衍生物）。
- 例：`烈焰使者`（c111）的战吼是 `[对敌方主战者造成 2 点伤害 → 消灭一个敌方随从]` —— 先打脸再解场，顺序就是面板里的顺序。
- **目标怎么选**：玩家出牌时只需为「链里第一条需要选目标的效果」选一个目标；其它条目若也需要目标、而玩家选的目标不适用，
  引擎会**自动挑第一个合法目标**并记一条日志（确定性顺序）。
- **旧卡表完全兼容**：只有 `effect_id / value / target`、`deathrattle_id / death_value` 的老卡照旧能读能打，
  卡面文本与 AI 判定都不变（链首会镜像回老字段，存档同时写出新旧两套键）。

### 2. 主动技能：随从 / 护符 / 城邦都能带，玩家花 PP 发动

- 卡牌管理里勾「启用技能」后可填：**技能名称 / 技能花费（PP） / 目标类型 / 每回合一次 / 技能效果链**（同样多段、按顺序结算）。
  **花费可以自由指定 0–10 PP**：`0` = 免费技能（法力 0 也能发），`10` = 一次花光全部 PP。
- **PP 就是现有的法力（能量点）**：回合开始 +1、上限 10，与出牌共用；发动技能会扣掉对应点数。
  界面上处处按 PP 显示：单位卡面右上角的角标直接写 `技能 2PP` / `技能 免费`，操作栏、悬停详情与战斗日志同理。
- **怎么发动**：点自己场上带技能的单位——
  - 不需要目标 → 立刻发动；
  - 需要目标 → 进入「选择技能目标」状态，点高亮目标发动；
  - 单位**本回合已用过技能 / PP 不足 / 在防御格里 / 被冻结**时，点它会**回落到原来的「选择攻击目标」**，操作栏给出不能发动的原因
    （例如「PP 不足：技能「秘法冲击」需要 2 PP，你现在只有 1」）。
- 规则：`每回合一次` 勾上时同回合只能发动一次；**防御格里的随从不能发动**（移出后即可）；**护符 / 城邦照样能发动**。
- 示例卡：`秘法守卫`（c112，花 2 PP 造成 3 点伤害，另带两条亡语）、`智慧祭坛`（a111，护符，花 1 PP 抽 1 张）。
  （内置卡表已加入这 3 张示例卡；若你本地已有 `user://cards.json`，用「卡牌管理 → 恢复默认卡表」即可拿到，或自己用新编辑器做一张。）
- 卡面与悬停详情都会显示技能（名称 / PP 花费 / 目标 / 每回合一次 / 技能效果链）。
- 卡表自检（`CardDB.config_errors()`）会一并检查：链里的未知效果 ID、缺衍生物 ID、目标错配、技能空链 / 目标不一致。

## 兵种（单位分类，类似影之诗的 士兵 / 指挥官）

* **先建后用**：管理员面板左侧「兵种」区里新建（ID / 名称 / 简介 / 配色），卡牌表单的「兵种」下拉才会出现它。
  内置「中立」不可删除 —— 没选兵种、或兵种后来被删掉的卡都归它（数据上仍存空 `troop_id`）。
* **可检索**：卡名 / 效果 / 关键字之外，**兵种名**也进检索；组卡界面与管理员卡表都有兵种筛选下拉。
* **当条件用**（这一条是兵种的主要用途）：
  * **效果链**：每条效果下面那行「条件」= 量 + 兵种 + 比较符 + 阈值，不满足就跳过这一条效果；
  * **瞬念召唤**：触发条件里选「本局 / 本回合该兵种进场数」「场上 / 墓地该兵种数」，再选兵种。
    例：`本局该兵种进场数「士兵」≥ 3` → 这张卡直接从牌库自动上场，这就是
    「某兵种进场到一定数量就触发某些卡」最省事的做法。
* **数据**：`data/troops.json` 是内置兵种，管理员改动写 `user://troops.json`；一张卡的兵种存在卡表
  `troop_id`（空 = 中立）。兵种被删时，原本挂着它的卡会自动改成「中立」。


## 主战者效果（照影之诗**一代**的「主战者に付与される効果」，不是二代纹章）

卡牌可以在某个时机把一条「监听器」挂到主战者身上，之后由引擎在事件发生时替它结算。
制作界面在卡牌编辑器最下面「主战者效果」区：清单 + 选中行编辑（可配多条）。

| 维度 | 可选项 |
| --- | --- |
| 赋予时机（这张卡发生什么事时挂上去） | 入场（打出）/ 离场 / 瞬念召唤 / 召唤入场 / 消失 |
| 赋予目标 | 自己主战者 / 对手主战者 |
| 监听事件（挂上之后什么时候结算） | 我方回合开始时 / 我方回合结束时 / 打出指定费用的卡时 / 抽到指定费用的卡时 / 指定费用的卡离场时 |
| 费用过滤 | -1 = 任意；N = 只对「费用 == N」的那张卡生效（只对后三种监听有意义） |
| 持续回合 | 0 = 本局永久；N = 该主战者再过 N 个自己的回合后失效 |
| 效果链 | 与战吼 / 亡语同一套效果（每条效果还能再配「条件」） |

* 例：赋予时机「入场」+ 监听「抽到 3 费卡时」+ 效果「造成 1 点伤害」+ 持续 5 回合
  = 这张卡打出后，我方在 5 个回合内每次抽到 3 费卡都造成 1 点伤害。
* 数据在卡表 `leader_effects` 数组里；解析 / 结算在 `scripts/LeaderEffects.gd`（加一个新监听事件
  = 注册一行 + 在 GameManager 对应时机调一次 `LeaderEffects.fire`）。
* 保存前会校验结构、空效果链与效果 ID；配置自检（`CardDB.config_errors`）同样会报。


## 二·新、界面流程（标题 → 主界面 → 匹配 → 对局）

```
启动（启动器 / F5）
   └─ scenes/Title.tscn   标题界面：游戏名 + 开始游戏 / 设置 / 退出游戏
        └─ scenes/Home.tscn  主界面：开始匹配（线上对战）/ 人机对战 / 创建·加入房间 / 设置 / 卡牌管理 / 返回标题
             ├─ 开始匹配 → NetSession 匹配：先扫局域网空房间（有就直接加入）
             │              等 4 秒仍没有就自己开房等对手（面板显示「已开房等待对手（房间 … 端口 …）」）
             │              匹配成功（真人坐上座位 1 / 客机收到 welcome）→ 切 scenes/Main.tscn 对局
             ├─ 人机对战 → GameManager.new_game() → 切对局
             └─ 创建 / 加入房间 → 老的大厅面板（手动指定房间 / 观战 / 重连令牌）
```

- 启动场景已从对局改为标题界面（`project.godot` 的 `run/main_scene`），双击启动器现在先看到标题界面。
- 对局界面仍然是原来的 `scenes/Main.tscn`：顶栏有「联机」按钮与联机状态（身份 / 延迟 / 等待重连）。
- 客机的起手换牌会**作为意图发给房主**执行（房主才是权威），不会出现"只有本机换了牌"。

## 二·补、联机对战（房主权威）

| 操作 | 说明 |
| --- | --- |
| **创建房间** | 顶栏「联机」→ 填房间名 / 端口（默认取设置里的 27015）/ 每回合时限 → 「创建房间」；房主就是权威，跑真正的规则 |
| **加入房间** | 同一面板里选局域网列表里的房间，或直接填房主 IP → 「加入」；满了会自动转**观战**（勾「观战」也可主动观战） |
| **开始对局** | 房主点「开始对局」双方同时开场（含起手换牌） |
| **断线与重连** | 掉线后房主**保留座位 60 秒**：客机重开游戏、用同一面板加入即可凭**重连令牌**回到原座位；超时判负 |
| **延迟** | 顶栏联机状态里显示 RTT（每 2 秒刷新） |

**权威模型**：房主跑 `GameManager`，客机只发「操作意图」并把房主下发的状态快照渲染出来——
客机不跑战斗规则，所以不存在两边结算不一致。
**隐藏信息**：快照按人定制，只有**自己的**手牌内容会下发（对手只给张数、牌库只给张数），观战者两侧都看不到内容。

## 三、规则实现清单

- **区域**：双方各有牌库 / 手牌（上限 10）/ 战场（上限 7）/ 墓地。
- **卡牌四分类**：
  | 类型 | 上场方式 | 能不能攻击 | 说明 |
  | --- | --- | --- | --- |
  | **随从** | 占一格 | 可以（当回合召唤的除外） | 有攻击力 / 生命值，常规随从 |
  | **法术** | 不占格子 | —— | 结算后进墓地 |
  | **护符** | 占一格 | 不能 | 有**耐久**（卡表里的 health），可以被伤害 / 被指定解掉；卡面效果在上场时立即结算一次（显示为「安放：…」） |
  | **城邦** | 占一格 | 不能 | 与护符同形，但**每套牌组最多只能携带 2 张**（整副牌组里城邦卡合计 ≤ 2） |
  护符 / 城邦都会占战场格子、照常被群体效果命中，耐久归零即被摧毁并进墓地。横置格只收**随从**。
- **城邦格**（**主战者左侧**那一格，**不占 7 格战场**）：上下两个主战者**左侧**各有一个，最多放一个城邦。
  **城邦只会被召唤进这个格子**（从手牌打出、或每 3 回合的规则触发），不会占战场格子；格子被占用时城邦牌打不出。
  格子空着时，
  **每 3 个自己的回合**判定一次（第 3 / 6 / 9… 个自己的回合开始时）：先从**牌堆**里随机召唤一个城邦（从牌堆移出），
  牌堆里没有就从**墓地**里召唤（从墓地移出）；牌堆与墓地都没有、或格子已被占用 → **这个回合不召唤**。
  判定没召唤成功时**不延后**：不会在下一回合补召唤，而是**等到下一个第 3 个自己的回合再判定一次**。
  **同一回合不会召唤第二次**；每 3 个回合**最多召唤一个**。自动召唤**不结算安放效果**（入场效果只在从手牌打出时结算，
  想补触发就用「触发一次入场效果」）。格子里的城邦与普通城邦一样有耐久、可被指定 / 被攻击 / 被解掉，被摧毁后进墓地，
  之后的判定还能把它从墓地召唤回来。双方各自计时（AI 也有自己的城邦格）。
- **起手换牌**：双方开局各抽 **4 张**；玩家可以在「起手换牌」面板里自选换掉任意张（选中的牌洗回牌库、重新洗牌后抽同样张数），
  也可以一张都不换。面板只列**起手那 4 张**——第 1 回合开始抽的那 1 张不在可换范围。AI 会把 **≥6 费**的起手牌最多换掉 2 张。
- **回合**：轮到自己的回合时法力上限 +1（最高 10）并抽 1 张，同时重置己方随从的攻击次数。
- **召唤当回合不能攻击**（除非拥有 **冲锋**）；**突袭** 当回合只能攻击随从，不能打脸。
- **嘲讽**：敌方存在嘲讽随从时，我方必须先攻击嘲讽随从。
- **圣盾**：免疫一次伤害后消失；**风怒**：每回合可攻击两次。
- **吸血**：造成伤害后，为你的英雄恢复**实际造成的伤害量**（被圣盾挡下或打在护甲上都不回血，治疗不超过上限）。
- **剧毒**：受到它伤害的随从会被**直接消灭**（被圣盾挡下时没有造成伤害，因此不触发；对英雄只算普通伤害）。
- **潜行**：无法被敌方**指定为目标**（不能被单体法术指定、不能被攻击），但**群体与随机效果照常命中**；攻击后解除。
  沉默会移除全部关键字与机制。
- **防御格**（原「横置格」；每条战场行正中那一格，类似游戏王把牌横摆）：放进去的随从
  **1 点以上的伤害一律限定为 1**（攻击 / 法术 / 战吼 / 群体 / 亡语一律减为 1）、**不能发动主动行为**
  （不能攻击、也不能发动主动技能 —— `can_use_skill()` 直接拦下并给出原因）、
  **敌方用技能指定这一侧的随从时只能选它**（群体与随机效果不受限，我方自己的技能也不受限）；
  **只有被对面随从的碰撞攻击打中才会撤出防御格**（法术 / 战吼 / 技能等非碰撞伤害只扣 1 点血、它留在里面；
  被圣盾挡下没掉血也不撤出）；**随从自身的战吼 / 亡语 / 关键字照常生效**。
  **调整限制**：只能**在自己的回合**把随从**移入**或**移出**防御格，而且**这两个动作一回合只能用一次**（共用一个名额）；
  不是自己的回合 / 本回合已经调整过 → 操作被拒绝并给出原因。从手牌直接把随从打进那一格也算一次「移入」。
  操作方式：拖到正中那一格 = 移入；把防御格里的随从**拖回我方后排** = 移出（后排随从不能随便挪格子）。同一侧同时只允许一个。
- **卡组规则（管理员可改）**：管理员面板左下角「卡组规则（全局）」可设置
  **卡组最少张数 / 卡组最多张数 / 同名卡最大携带数**（1–9 张），以及**按种类的总携带上限**
  （随从 / 法术 / 护符 / 城邦各自「每张牌组最多带几张」，0 = 不限，例如「法术最多 30 张」）。
  点「应用卡组规则」立即生效并写入 `user://deck_rules.cfg`（「张数三段」与「种类上限」两节配置互不覆盖）。
  **同名上限的默认口径由稀有度决定**：**传说 = 1 张，其余 = 全局同名上限**；管理员还能在卡牌编辑器的
  「携带上限」里给**单张卡**单独设上限（优先级最高，覆盖稀有度与全局同名上限）。
  生成牌库 / 组卡时：每种卡按上述口径放相应份数（城邦仍受「整副牌组合计 ≤ 2 张」限制，且仍受对应种类上限约束），
  **不足最少张数自动轮转补足、超过最多张数从尾部裁掉**；默认值 `30 / 200 / 2` 与改动前完全一致（牌库张数不变）。
- **战吼**：随从上场后立即结算；**亡语**：随从死亡时结算。
- **入场效果的触发规则**（随从 = 战吼，护符 / 城邦 = 安放）：
  | 上场方式 | 会不会结算入场效果 |
  | --- | --- |
  | **从手牌打出** | 会（唯一的自动结算时机） |
  | **召唤入场**（衍生物 / 复制 / 亡语召唤 / 城邦格每 3 回合判定） | **不会** |
  | 由卡牌效果 **「触发一次入场效果」** 指定某个已在场的单位 | 会，**一次触发只结算一次** |
  想让召唤上场的单位也吃到入场效果，就用「触发一次入场效果」（`trigger_entrance`，默认目标：我方随从，含城邦格里的城邦）。
  卡面效果互相触发也有保护：「入场效果里再触发入场效果」最多套 3 层就停手，不会无限递归。
  对应测试：`tools/entrance_trigger_test.gd`。
- **费用 / 复制 / 牌库调度**（刻意拆成最小原语，方便在效果链里自由组合）：
  | 效果 | 数值 | 目标 | 作用 |
  | --- | --- | --- | --- |
  | 手牌费用增加 | +N | 英雄（选哪一方） | 该方手牌**全部** +N 费（加在卡实例上；填负值就是减费） |
  | 复制本随从 | N | 不需要（也可指定某个随从） | 在战场上再放 N 个本随从的副本 |
  | 复制本随从进牌库 | N | 不需要 | 把 N 份副本随机洗进自己的牌库 |
  | 复制随从进牌库 | N | 我方随从 | 把目标随从的 N 份副本洗进自己的牌库（随从本身不动） |
  | 复制手牌进牌库 | N | 英雄（选哪一方） | 随机复制该方 N 张手牌，洗进自己的牌库（来源手牌不动） |
  | 呼唤（指定卡） | — | 不需要 | 找到**填的那个卡 ID** 召唤上场（找不到就什么都不结算） |
  | 呼唤（费用 ≤ N） | N | 不需要 | 随机挑一个费用 ≤ N 的随从召唤上场 |
  | 随机呼唤 | — | 不需要 | 随机挑一个随从召唤上场 |
  | 上面三条的「临时」版 | 同上 | 不需要 | 同样召唤，但它在拥有者**下一个自己的回合结束时回到手牌**（瞬念召唤式登场） |
  统一口径：复制的是**卡牌本体**（再次被召唤不会连锁触发它的入场效果）；进牌库一律放**随机位置**；
  被召唤的那张**真的离开原地**（墓地里的会被亡招出来）；战场满 / 手牌满 / 找不到卡只会记日志跳过，不会报错。

  **两条限定词缀**（效果链每一行右侧多出来的两项，只有需要的效果才显示）：
  | 限定词缀 | 取值 | 用在哪 | 含义 |
  | --- | --- | --- | --- |
  | **来源** | 牌库 / 墓地 / 牌库优先→墓地 | 6 条呼唤效果 | 限制去哪儿翻牌。「牌库优先→墓地」与城邦格同为一套口径：牌库里有就用牌库的，没有才从墓地亡招 |
  | **持续回合数** | 0 = 永久（默认）/ N | 手牌费用增加 | N 回合后自动还原：到**受影响那一方**第 N 个回合结束时把费用还回去，已经打出（不在手上）的卡不受影响 |
  卡面文本会自动带上这两条限定（例如「使目标一方的手牌费用 +2（持续到目标一方第 1 个回合结束）」）。
  对应测试：`tools/cost_copy_summon_test.gd`。
- **瞬念召唤**（影之诗的 Invocation）：一张卡**自己**待在牌库里、满足条件时自动上场，不需要任何人打出它。
  在卡牌管理里给一张卡勾上「启用瞬念召唤」，再挑**触发条件**（量 + 比较符 + 阈值）+ **触发时机**即可：
  | 配置项 | 取值 | 含义 |
  | --- | --- | --- |
  | 触发条件 | 见下表（13 个「量」） | 看哪一个量 |
  | 比较符 | `<=` `>=` `=` `!=` `<` `>` | 这个量跟阈值怎么比 |
  | 阈值 | 0–30 | 比对的那个数 |
  | 触发时机 | 任意时机 / 我方回合开始 / 我方回合结束 | 在哪些检查点替它判定（都在**自己**回合内） |
  可读的**量**有 13 个（都在 `scripts/InvokeConditions.gd`，新增一个只要加一行 `_reg`）：
  回合数、我方已进行回合数、我方剩余法力、我方法力上限、我方英雄生命、敌方英雄生命、
  我方手牌张数、我方随从数、敌方随从数、本回合已打出牌数、
  本回合我方死亡随从数、本局我方累计死亡随从数、我方墓地张数。
  条件 = **量 + 比较符 + 阈值**（与《影之诗》反编译实现同一套模型：
  每个 `SkillConditionXxx` 只读一个量，比较符由 `SkillCompareFuncCreator` 统一给六种），
  所以 13 个量 × 6 种比法 = 78 种条件，不用为「手牌 ≥ N」和「手牌 ≤ N」各写一个 ID。
  检查点都在**自己回合内**：**回合开始时**（轮到谁才替谁判定）、**回合结束时**、
  **自己打出一张牌之后**、**自己攻击结算之后**（后两个只结「任意时机」）。
  这三个时机对应 SV 技能上的 `OnSelfTurnStartStart` / `OnSelfTurnEndStart` 两个字段
  （SV 另外还有 `OnOpponentTurnStartStart` / `OnOpponentTurnEndStart`，本作**没采用**）。
  五条规则（第 1、2 条与《影之诗》一致，第 3–5 条是本作的口径）：
  1. **它不是战吼**：应召上场**不结算**入场效果（想要就自己配「触发一次入场效果」）；
  2. **同名卡（同一个卡 id）的瞬念召唤每个回合只结算一次**（牌库里 3 张同 id 也只出来 1 张）；
  3. **以卡面原始数值登场**：这张卡在牌库里攒下的改动（费用被减半、身材被加减、
     被赋予关键字……）不带到战场上，上场的是卡表里那一张原始卡；
     「呼唤」从牌堆拉出来的同样按这条来（`scripts/GameManager.gd` 的 `_clean_deck_card`）。
  4. **只在自己的回合结算**：每个检查点只替当前行动方判定，对面在动的时候
     （它的回合开始 / 中间 / 结束、它打出牌）你的卡不会从牌库里冒出来；
     「任意时机」也一样 —— 它指的是「自己回合内的任意检查点」，不是「任意玩家的回合」。
     旧卡表里若带着那两个「对手回合」时机，读进来会迁到对应的「我方回合」时机上。
  5. **没有空置格 → 这张卡「消失」**（影之诗的消失：从游戏中移除，**不进战场 / 手牌 / 墓地**）；
     有空置格时才会应召到空置格上（随从 / 护符看 7 格，城邦看城邦格）。
  条件没达成时它老实留在牌库里等下一次（有日志说明原因）。

  **应召之后：先结算「瞬念召唤效果」，再执行「基础机制（去向）」**
  （这是本作为瞬念召唤补的第二段，两块都与战吼 / 亡语**完全独立**）：

  | 段落 | 面板上的位置 | 能否为空 | 说明 |
  | --- | --- | --- | --- |
  | **瞬念召唤效果** | 「瞬念召唤效果」（一条效果链） | **可以留空** | 与战吼 / 亡语独立的一段效果，按链顺序结算 |
  | **基础机制（去向）** | 「基础机制（去向）」下拉 | **必选，不能为空** | 效果结算完之后这张卡留在哪 |

  去向共四种：**留在场上**（默认，与改动前一致）/ **返回手牌**（手牌满则销毁）/
  **进入墓地** / **由玩家选择**（上场后弹三选一：保留在场 / 返回手牌 / 进入墓地；不选则默认留在场上）。
  顺序固定为「先效果、后基础机制」——例如「抽 1 张后返回手牌」会先抽牌再回手。

  对应测试：`tools/invocation_test.gd`（含界面：**只随从 / 护符 / 城邦能配它**，法术无处可去会被拦下）。
- **参考主流卡牌游戏拓展的机制**（炉石 / 影之诗）：
  | 机制 | 出处 | 效果 |
  | --- | --- | --- |
  | **复生** | 炉石 | 第一次死亡时以 1 点生命回到战场（亡语照常结算一次） |
  | **过载 N** | 炉石 | 打出后下一回合可用法力减少 N（法力上限不减） |
  | **连击** | 炉石 | 本回合已经打出过其它牌时，追加执行卡面配置的连击效果 |
  | **法术伤害 +N** | 炉石 | 你的伤害性**法术**额外造成 N 点（多张叠加；随从战吼、消灭类效果不受影响） |
  | **发现** | 炉石 / 影之诗 | 从三张随机卡牌里三选一，选中的加入手牌（弹窗挡住底下操作） |
  | **倒计时 N** | 影之诗护符 | 每到自己回合开始 -1，归零时被摧毁 |
  新增卡：不灭骸骨 / 超载法师 / 计时圣坛 / 影袭（卡表 71 张）。MTG 来源的词条（飞行 / 先攻 / 践踏 / 警戒 / 辟邪）已按要求删除。

## 打包发布：单独游戏与启动器

一条命令把项目封成**可以拷到别的电脑上直接玩**的目录（自带启动器）：

```powershell
powershell -ExecutionPolicy Bypass -File build\build_release.ps1              # 打包（默认 release\CardGame\）
powershell -ExecutionPolicy Bypass -File build\build_release.ps1 -SelfTest    # 打包后真的拉起一次游戏
powershell -ExecutionPolicy Bypass -File build\build_release.ps1 -SkipZip     # 不打 zip
powershell -ExecutionPolicy Bypass -File build\verify_release.ps1             # 只验证已打好的包

# 成品不放项目里：整个游戏文件夹直接输出到项目外的独立文件夹，拷走就能玩
powershell -ExecutionPolicy Bypass -File build\build_release.ps1 -OutDir "D:\CardGame游戏"
```

`-OutDir` 可以指向任何地方（支持相对路径）。产出就是**那一个自包含的文件夹**
（另有同名的 `<文件夹名>-v<版本>-win64.zip` 生成在它**旁边**），项目里因此只留源码。
默认（不给 `-OutDir`）产出 `release\CardGame\` 与 `release\CardGame-v<版本>-win64.zip`：

| 文件 | 说明 |
| --- | --- |
| `Launcher.exe` | **启动器，唯一入口**。.NET Framework 自带，不用装任何运行库 |
| `launcher.ini` | 窗口模式 / 分辨率 / 运行时类型 / 日志与存档路径（界面上改完自动写回） |
| `logs\` | `launcher.log`（启动器）+ `godot.log`（游戏，每次启动覆盖） |
| `game\CardGame.exe` | 游戏主程序 |
| `game\game.pck` | 游戏资源包（12.7 MB，导出时已排除 `tools/ docs/ screenshots/ *.md` 等） |
| `使用说明.txt` | 给玩家看的运行说明 |

启动器能做的：**开始游戏**、选窗口 / 全屏 / 最大化与分辨率（默认取 `project.godot` 的 1440×900）、
**检查文件**（缺主程序 / 资源包会直接点出来）、**打开日志**、**打开存档目录**，
以及游戏退出码非 0 时弹提示（崩溃不再是无声关闭）。参数由它拼好后传给主程序。

**两种运行时，脚本自动挑**：

| runtime | 条件 | 形态 |
| --- | --- | --- |
| `template` | 装了官方导出模板（`%APPDATA%\Godot\export_templates\<版本>\windows_template_release.exe`） | `--export-release`，PCK 内嵌进 exe → 真正的单文件游戏（约 40 MB） |
| `editor` | 没装模板（离线环境的兜底） | 导出 `game.pck` + 复制 Godot 运行时二进制来加载它，玩法完全一致，主程序约 180 MB |

联网后在编辑器里装一次导出模板（编辑器 → 管理导出模板），重新打包即自动切到 `template`。

**踩到的坑（已经绕开，留档）**：用 Godot 编辑器二进制当运行时时，它启动时会把
`user://logs/godot.log` 轮转复制一份，这一步失败会直接崩（退出码 `0xC0000005`，
`ERROR: Failed to open 'user://logs/...log' at: copy (core/io/dir_access.cpp:429)`）。
启动器因此固定传 `--log-file <发布包>\logs\godot.log`，并预先保证 `user://logs` 里有文件。
所以**入口必须是启动器**：直接双击 `game\CardGame.exe` 不会进游戏（资源包也刻意不与 exe 同名，
避免走「自动加载同名 pck」那条会崩的路）。用官方导出模板打包时没有这个问题。

存档在开发版与发布版之间是同一份：`%APPDATA%\Godot\app_userdata\卡牌游戏框架\`
（`cards.json` 卡表 / `decks.json` 卡组 / `settings.cfg` 设置），重装游戏不影响。

### 后续加美术素材：只改文件名，不改代码

自备素材统一放 **`assets/art/`**（约定目录；目录 / 文件缺失都自动回落，不影响运行）：

| 素材 | 放哪 / 怎么命名 | 生效方式 |
| --- | --- | --- |
| 卡面 | `assets/art/card_art/<卡 id>.png`（png / jpg / webp） | **文件名 = 卡 id**，优先级高于卡表里的 `art_path`：丢进去这张卡立刻换图（旧存档、新建的卡都不用再进管理员面板填路径） |

| 语音 / 音效 | `assets/art/voice/<事件名>.wav`（事件名同 `SoundFx`：play / attack / win / lose / button / turn_start …） | **文件名 = 事件名**；WAV 免 `.import`（`AudioStreamWAV.load_from_file` 兜底），拷进去就能播，且优先于逆向导入素材 |
| 场景背景 | 管理员面板「美术」里选任意图片（存 `user://art.cfg`） | 与卡表分离，删卡表不影响背景 |

优先级：`assets/art/`（自备）＞ `assets/sv/`（逆向批量导入，`tools/import_sv_art.gd`）＞ 代码内置（纯色 / 合成音）。
约定的解析都写在 `scripts/ArtStore.gd` 文件头；想换一套目录也不用改代码（`ArtStore.use_art_root` / `SoundFx.set_sample_dirs`）。

## 扩展架构：不改内核就能加机制 / 卡牌 / 美术 / 语音 / 特效（本轮新增）

> **详细配方见 [`docs/extending.md`](docs/extending.md)**（每一类扩展都有可复制的代码片段）。
> 这一节只讲「有什么、放哪里」。

| 扩展点 | 入口 | 说明 |
| --- | --- | --- |
| **扩展包** | `mods/<包名>/mod.json`（或 `user://mods/…`） | 一次把卡牌 / 机制 / 效果 / 特效 / 语音 / 卡图全接进来；**无需改代码、无需重新导出**。装载结果看启动日志 `[Mods]`。例：`mods/example/` |
| **机制（关键字）** | `mod.register_mechanic(...)` / 内核 `Mechanics._reg(...)` | 关键字 + 名称 + 说明 + 钩子 + 标志位；卡表 `keywords` 写 key 即生效。运行期关键字 ID 从 `CardData.MOD_KEYWORD_BASE`(=1000) 起，绝不与内置枚举冲突 |
| **卡牌效果** | `mod.register_effect(...)` / `CardEffects.register(...)` | ID + 名称 + 文本模板 + 默认目标 + `Callable`；注册后自动进卡面文本、悬停详情、管理员面板与 AI 评估 |
| **触发时机** | `CardTriggers._reg_event(...)` + 一个派发点 | 现有时机含本轮新增的 **攻击时 / 受到伤害时**（影之诗的 攻撃時 / ダメージを受けた時） |
| **条件指标** | `EffectConditions._reg(...)` | 量 + 比较符 + 阈值；本轮新增 **我方 / 敌方主战者生命、生命上限、牌库张数、手牌张数、场上单位数**，觉醒 / 共鸣这类判定直接可用 |
| **卡图** | `assets/art/card_art/<卡 id>.png`、扩展包 `card_art_dir`、`data/card_art_map.json` | 解析优先级：按卡 id 命名的文件 ＞ 映射表 ＞ 卡表 `art_path` ＞ 散列兜底 |
| **卡背** | `assets/art/card_back.png` / `assets/sv/card_back.png` / 扩展包 `card_back` | **抽牌堆、敌方手牌、飞牌共用同一张牌背**（本轮已接入《影之诗》原版卡背） |
| **战场预设** | `assets/art/board/*.png` | 目录里第一张自动成为竞技区背景（有图时竞技区面板自动半透明透出底图）；`assets/art/board/arena_default.png` 已内置一张 |
| **通用音效** | `assets/art/voice/<事件名>.wav`、扩展包 `voice_dirs` | 文件名 = 事件名；WAV 免 `.import`，拷进去就播 |
| **卡牌语音** | `<素材根>/<卡 id>/<事件>*.wav`、`data/voice_map.json`、扩展包 `card_voice_dirs` / `voice_map` | 事件：`play / summon / attack / death / skill / damage / turn / win / lose`；同一事件多个文件随机挑一个；没有语音自动回落通用音效 |
| **表现动画** | `scripts/BattleFx.gd`（`Main.battle_fx()`） | `play_card` 出牌飞牌 / `death` 破坏消失 / `summon` 召唤登场 / `burst` 通用碎裂；绝对时钟推进，跟随「动画速度」设置 |
| **扩展包状态袋** | `GameManager.mod_state` | 扩展包自己的记账放这里，不污染内核字段 |

**本轮顺带修掉的实打实的坑**

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | `SoundFx.play()` 里写着 `if false: return`，**真实语音素材永远播不出来** | 逆向导入的语音 / 自备 wav 一直是摆设；现在「素材优先，没有才用合成音」，且素材播放器池 4 个避免互相掐断 |
| 2 | `GameManager.card_played` 信号**没人接**，管理员配的「出牌特效」从未生效 | 现在出牌会播特效 + 卡牌语音 + 飞牌动画 |
| 3 | 扩展包卡牌会被写进 `user://cards.json` | 删掉扩展包后存档里留一堆孤儿卡；现在扩展包卡牌**不落盘**，也不参与 `save_cards()` |
| 4 | 运行期登记的机制 key 反查表下标写错（`keyword_key` 永远返回空串） | 外部机制的卡表 key 读不出来；已修并加断言 |
| 5 | 扩展包脚本实例被回收，注册的 `Callable` 变成 `null::func` | 外部效果一调用就报错；现在 `ModLoader` 持有脚本实例引用 |
| 6 | `AdminPanel` 对空下拉调用 `select(0)` | 每次打开管理员面板都刷一条引擎错误；已加 `item_count > 0` 守卫 |
| 7 | 卡表自检在扩展包装载**之前**跑 | 扩展包卡牌用的效果被误报成「未知效果」；现在等 `Mods.ready_done` 之后再自检 |

**照《影之诗》补进来的机制**

| 机制 | 出处 | 落地 |

| **觉醒（覚醒）** | 影之诗 | 新关键字 `awaken`：我方主战者生命 ≤ 10 时 +1/+1（只结算一次，之后保留）。钩子 `on_turn_start` + `on_damaged`，阈值 `Mechanics.AWAKEN_HP` |
