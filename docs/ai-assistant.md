# AI 助手浮窗（侧边栏）

> 从右侧滑出的 AI 对话浮窗 + 常驻的圆形「AI」按钮；任何界面（标题 / 主界面 / 对局）都能呼出。
> 接任何 **OpenAI 兼容** 的聊天接口（DeepSeek / OpenAI / 通义 / Kimi / 本地 Ollama、LM Studio…）。
> 本文说明「怎么用、怎么配、怎么改」，以及实现口径。

## 1. 怎么用

| 入口 | 位置 |
| --- | --- |
| 圆形「AI」按钮 | 右上角常驻；点开 / 收起（抽屉打开时按钮随抽屉左缘滑动，不压内容） |
| 顶栏按钮 | 对局顶栏「AI 助手」、主界面按钮行的「AI 助手」 |
| 快捷键 | `F2` 开合（对局内外都可用） |
| 收起 | 抽屉右上角「收起」、`Esc`（第一次先松开输入焦点，第二次才关窗） |

抽屉里的三样东西：

* **快捷指令**：`分析局面` / `推荐出牌` / `找卡` / `机制说明`——点了就等于替你把这句话发出去，
  AI 会自己按需调工具读局面 / 查卡表；
* **对话区**：AI 回复支持少量 Markdown（`**加粗**` / `` `代码` `` / `# 标题` / ``` 围栏 ```）渲染；
* **输入行**：回车发送；回复中「发送」变成「停止」，可以随时中断。

对局中打开浮窗时，**打字不会撞上游戏热键**：输入框有焦点时，空格（结束回合）/ `1-9`（选牌）/
`Tab`（记牌器）等全部让路（`Main._input()` 开头检查 `AiAssistant.input_focused()`）。

浮窗与**记牌器抽屉互斥**：两者都贴右边缘，打开一个会自动收起另一个。

## 2. 怎么配（接口 / 密钥 / 模型）

三个入口，都是同一个窗口：

* 浮窗标题栏的「设置」；
* 游戏「设置」窗口里的「AI 助手浮窗 → 配置接口 / 密钥 / 模型…」；
* 直接手改 `user://ai.cfg`（改完重启或再开一次设置窗口生效）。

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 接口地址（Base URL） | 会拼 `/chat/completions`；已含该后缀时原样使用 | `https://api.deepseek.com/v1` |
| API Key | 只存在本机 `user://ai.cfg`；本地服务可留空 | 空 |
| 模型名 | 例如 `deepseek-chat` / `gpt-4o-mini` / `qwen-plus` | `deepseek-chat` |
| 温度 | 0–2，越高越有创意 | 0.7 |
| 单次回复最大 token | 64–8192 | 2048 |
| 带上的历史消息条数 | 2–100（越大越费 token） | 24 |
| 流式输出 | 逐字显示；部分自建网关不支持，关掉后整段返回 | 开 |
| 系统提示词 | AI 的身份与回答纪律（**建议保留工具调用格式说明**） | 见 `AiConfig.DEFAULT_SYSTEM_PROMPT` |

> 没配好时浮窗仍可用：发消息会直接提示「AI 接口还没有配置好」，不会静默失败。

## 3. 它能做什么（工具 / agent 味在哪）

AI 不是纯聊天——它有一套**只读工具**，需要事实时会自己查，再基于结果回答（这就是「agent 味」）：

| 工具 | 作用 |
| --- | --- |
| `card_search` | 按名字 / id / 种类 / 费用上限 / 关键字检索卡表（最多列 40 条） |
| `card_detail` | 查一张卡的完整资料：效果链、亡语、关键字、技能、瞬念召唤、融合、职业与兵种 |
| `game_state` | 读当前局面：回合数、轮到谁、双方血量 / 护甲 / 法力、**我方手牌明细（标出能不能出）**、战场明细、横置格、最近日志 |
| `mechanic_info` | 查关键字（嘲讽 / 圣盾 / 潜行…）的结算规则与互斥关系 |

调用协议（写在系统提示词里，AI 按需使用）：

```
[[tool: {"name":"card_search","args":{"query":"龙","max_cost":5}}]]
```

一轮对话的实际流程（`AiAssistant._start_round()` / `_on_round_finished()`）：

```
用户消息
  └─ 请求 #1（system + 历史）
       ├─ 回复里没有工具调用 → 直接落定，结束
       └─ 回复里有工具调用 → AiTools.run_tool() 执行
            └─ 结果作为 tool 消息回灌 → 请求 #2 → …（最多 4 轮，防死循环）
```

**口径**：工具目前全是**只读**的——AI 会读局面、查卡表、给建议，但不会替你点按钮。
想加「代打」类操作，见下一节。

## 4. 代码结构与职责

| 文件 | 职责 |
| --- | --- |
| `scripts/AiConfig.gd` | 自动加载单例 `AiConfig`：接口 / 密钥 / 模型 / 生成参数的读写与落盘（`user://ai.cfg`） |
| `scripts/AiClient.gd` | OpenAI 兼容聊天客户端：请求组装、SSE 流式解析、非流式回退、错误提取（纯逻辑，无 UI） |
| `scripts/AiTools.gd` | 工具集：目录 / 提示词块、卡表检索、局面读取、机制解释、工具调用解析与可见正文剥离 |
| `scripts/AiSidebar.gd` | 浮窗控件：抽屉 + 圆形按钮 + 对话渲染（Markdown→BBCode）+ 输入 / 焦点守卫 |
| `scripts/AiAssistant.gd` | 自动加载单例 `AiAssistant`：全局 CanvasLayer、对话调度、工具循环、`F2`、设置窗入口 |
| `scripts/AiSettingsDialog.gd` | 接口配置窗口（失焦即落盘） |
| `tools/ai_assistant_test.gd` | 无头测试：配置 / 客户端 / 工具 / 调度 / 界面 / 集成（111 项） |

**为什么浮窗挂在自动加载单例上**：对话历史与抽屉状态要**跨场景保留**（标题 → 主界面 → 对局），
挂在场景里会被一起销毁；挂 `CanvasLayer`（layer 64，在拖拽层 128 之下）则任何界面都能呼出，
且拖拽中的幽灵卡仍盖得住浮窗。

**为什么单独一份 `ai.cfg`**：密钥与生成参数属于「可选功能」的配置，与游戏偏好分开存更干净；
不配也能正常玩，只是浮窗会提示未配置。

## 5. 加一个工具（给 AI 新能力）

三步，都在 `scripts/AiTools.gd`：

1. **写执行函数**（返回给 AI 看的纯文本）：

   ```gdscript
   static func my_tool(query: String) -> String:
       # 读 CardDB / GameManager 或任何数据，拼成人话返回
       return "结果…"
   ```

2. **注册进 `catalog()`**（AI 靠这段说明书知道有这个工具）：

   ```gdscript
   {"name": "my_tool", "desc": "这个工具干什么（写清楚入参含义）", "args": {"query": "字符串"}},
   ```

3. **接进 `run_tool()`** 的 `match`：

   ```gdscript
   "my_tool":
       text = my_tool(str(args.get("query", "")).strip_edges())
   ```

返回文本会被 `MAX_RESULT_CHARS`（6000 字）截断，超长时自己收口。

**想加「操作类」工具**（代打）：执行函数里直接调 `GameManager` 的既有入口
（如 `play_card` / `attack` / `end_turn`）即可，但要在工具说明里写清副作用，
并考虑加一层玩家确认——目前刻意没做，避免 AI 误操作。

## 6. 测试

```bat
godot --headless --path <项目目录> --script res://tools/ai_assistant_test.gd
```

覆盖：配置默认值 / 越界夹紧 / `endpoint()` 拼接 / 存读往返；客户端请求体与请求头、
SSE 分片解析（含跨片行缓冲）、非流式提取、错误提取；工具目录、卡表检索、卡详情、
机制解释、局面读取（含「不泄露对手手牌」）；工具调用解析（标准格式 / JSON 壳 / 坏格式）、
历史裁剪、系统提示词拼装；抽屉开合几何、消息渲染（Markdown / BBCode 转义）、
打字守卫、按钮命中；以及 `Main.tscn` 顶栏按钮联动。

> 真实 HTTP 往返没有进自动化测试（无头环境起假服务器不稳）；请求组装与响应解析都有单测覆盖，
> 端到端请用真实接口试一次：填好配置 → 问一句「嘲讽是什么意思」。

## 7. 已知取舍

* **工具是只读的**：AI 给建议、不代打（想开见第 5 节）；
* **不塞全卡表进提示词**：70+ 张卡全量塞进去太贵，改成按需检索（`card_search` / `card_detail`）；
* **对手信息按规则隐藏**：`game_state` 只给对手的手牌张数，不给内容；
* **密钥明文存本机** `user://ai.cfg`：单机游戏、配置不外发；介意的话可以不填（用本地模型）；
* **工具循环上限 4 轮**：防模型反复调工具不产出结论；
* **历史裁剪**按条数 + 总字符（40000）双重上限，且不会把孤儿 `tool` 消息留在开头（服务端会报错）。
